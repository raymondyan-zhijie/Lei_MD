## 1. 项目背景

[Microsoft MarkItDown](https://github.com/microsoft/markitdown)（⭐ 136,328 stars · 9,300 forks）是 Microsoft 开源的 Python 文件转 Markdown 工具，支持 PDF、Word、Excel、PowerPoint、HTML、EPUB、图片（OCR）、音频（转录）、YouTube 等 20+ 种格式。然而它仅有命令行接口，对 Windows 普通用户不够友好。

本项目（**Lei_MD**）基于 MarkItDown 构建一个 **大而全、离线运行的 Windows 原生图形界面**，让非技术用户也能轻松拖拽文件完成转换。

## 2. 用户画像

| 角色 | 需求 | 痛点 |
|------|------|------|
| 学生/研究者 | 把论文 PDF、课程 PPT 转 Markdown 整理笔记 | 命令行不会用 |
| 内容创作者 | 把 Word/网页文章转 Markdown 发布 | 来回切换工具繁琐 |
| 办公人员 | 批量转换 Excel/Word 文档为文本 | 格式丢失、步骤多 |
| 开发者 | 快速预览文件 Markdown 输出 | CLI 不直观 |

## 3. 功能需求

### 3.1 核心功能（MVP — v1.0）

| 编号 | 功能 | 优先级 | 描述 |
|------|------|--------|------|
| F1 | 文件拖拽转换 | P0 | 拖拽单个或多个文件到窗口，自动识别格式并转换 |
| F2 | 格式支持列表 | P0 | 支持 MarkItDown 核心格式（PDF/Word/Excel/PPT/HTML/EPUB/图片/CSV/JSON/XML/ZIP） |
| F3 | 转换结果预览 | P0 | 内置 Markdown 实时预览窗口，支持渲染视图 |
| F4 | 一键复制/导出 | P0 | 复制 Markdown 原文到剪贴板、导出为 .md 文件 |
| F5 | 批量转换 | P1 | 多文件并行/顺序批量转换，进度条显示 |
| F6 | 输出目录选择 | P1 | 用户可指定输出目录，默认同源文件目录 |
| F7 | 历史记录 | P1 | 保留最近 50 条转换记录，支持回看 |

### 3.2 进阶功能（v1.1+）

| 编号 | 功能 | 优先级 | 描述 |
|------|------|--------|------|

### 3.3 非功能需求

| 编号 | 需求 | 指标 |
|------|------|------|
| NF1 | 性能 | 单文件 <5MB 转换在 3 秒内完成 |
| NF2 | 兼容性 | Windows 10/11，Python 3.10 ~ 3.13 |
| NF3 | 安装包大小 | 大而全单安装包（详细预估见 [05 §3.1](05-release-plan.md)） |

## 4. 约束条件

- **依赖 MarkItDown 库**：核心转换能力由上游库提供，本项目只做 GUI 封装
- **大而全 + 离线**：单安装包一次性集成全部 20+ 格式所需依赖，**完全离线运行**，用户不需联网
- **必须兼容 Windows**：使用 PyInstaller + NSIS 打包为标准 Windows 安装程序
- **遵循 MIT 许可**：本项目（Lei_MD）为**独立 MIT 授权**的 GUI 封装，与上游 MarkItDown（MIT）独立发布但保持协议兼容；分发时需保留双方版权声明。SPDX 标识符见 [LICENSE](../LICENSE)
- **Python 生态**：GUI 框架限定 Python 生态（PySide6），降低维护成本

### 5.1 异常场景定义（用户视角）

> 需求层先定义"用户看到什么行为"，架构/测试再去实现细节。
> 错误码 ID 与 02 §6.1 一一对应。

| 场景 | 用户可见行为 | 错误码（详见 02 §6.1） |
|------|-------------|------------------------|
| 文件不存在 / 拖入后被删除 | 文件列表标 ❌ 失败，悬停看详情 | `E_FILE_001` |
| 文件被其他程序占用 | 文件列表标 ❌ 失败 + 提示"请关闭占用程序后重试" | `E_FILE_001` |
| **0 字节空文件** | 文件列表标 ❌ 失败 + 提示"文件为空，跳过" | `E_FILE_002` |
| **超大文件 (>500MB)** | 拒绝处理 + 提示"文件超出 500MB 限制" | `E_FILE_003` |
| 恶意文件名 (路径遍历 `../../`) | 拒绝 + 提示"非法文件名" | `E_FILE_004` |
| 拖入不支持格式 (`.xyz` 等) | 拒绝 + 提示"暂不支持此格式（v1.0 支持 20+ 格式，详见 F2）" | `E_FILE_005` |
| **拖入音频 (mp3/wav)** | v1.0 明确提示「v1.1+ 支持」（[01 F9a](#32-进阶功能v11)） | `E_FILE_006` |
| **密码保护 PDF / 加密 Office** | 文件列表标 ❌ 失败 + 提示"文件受密码保护，暂不支持" | `E_CONVERT_001` |
| 文件格式损坏（docx 实际是 zip 损坏等） | 文件列表标 ❌ 失败 + 提示"文件已损坏，无法解析" | `E_CONVERT_002` |
| 转换过程中用户强关 | 下次启动检查 `processing.lock` 清理未完成文件 | `E_SYS_001` |
| 输出路径不可写 (磁盘满 / 权限不足) | 弹模态对话框 + 提供"打开输出目录"按钮 | `E_SYS_002` |
| 路径超过 Windows MAX_PATH 260 | 自动检测并尝试 `\\?\` 前缀；仍失败则报错 | `E_SYS_003` |
| 转换引擎崩溃 (Python traceback) | 捕获后不退出 + UI 红条 + 上报日志 | `E_INTERNAL_001` |
| SQLite 历史数据库损坏 | 下次启动检测 → 自动备份原文件 + 重建空库 | `E_INTERNAL_002` |
| 配置文件 (`config.json`) 损坏 | 下次启动检测 → 备份原文件 + 重置为默认值 | `E_INTERNAL_003` |
| 更新文件下载中断 / 校验失败 | 保留旧版本 + 提示重试 | `E_UPDATE_001` |
| 应用内「检查更新」网络失败 | 静默忽略 + 状态栏提示"无法连接服务器" | `E_UPDATE_002` |
- ✅ 应用启动时**自动检测损坏**（SQLite/config）并恢复
